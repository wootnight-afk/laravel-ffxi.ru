1. Обзор
Русскоязычное сообщество игроков Final Fantasy XI (сервер Phoenix).
Реконструкция классического сайта-сообщества 2000-х на современном стеке Laravel с сохранением духа оригинала и добавлением современных UX-практик: фиксированная шапка и футер, светлая/тёмная темы, адаптивность, отдельный админ-контур на Filament.

Источники (скриншоты в docs/design/):
ffxi.ru.png, news.png, gallery.png, players-00.png, players-01.png, login.png, contacts.png.

Приоритет достоверности:

Точно — каркас: фиксированная шапка + фиксированный футер, порядок блоков, состав страниц, набор ролей.

Близко — цветовая гамма (бирюзовый акцент) и общий колорит.

Свободно — типографика деталей, отступы, скругления.

4. Каркас — обновлённый принцип
Ключевое отличие от черновика: фиксируется не только шапка, но и футер.

text
┌──────────────────────────────────────────┐
│ Header (position: fixed, top: 0)         │ ← всегда виден
│ ├─ Логотип (клик → главная)              │
│ ├─ Кнопки: Новости, Галерея, Игроки,     │
│ │   Контакты                              │
│ └─ Правая зона: [☀/🌙] + «Авторизация»   │
├──────────────────────────────────────────┤
│                                          │
│  Content (max-width: 1000px, padding-top │
│  = header-height, padding-bottom =       │
│  footer-height)                          │
│                                          │
├──────────────────────────────────────────┤
│ Footer (position: fixed, bottom: 0)      │ ← всегда виден
│ ├─ «Community of Players FFXI — Phoenix» │
│ └─ Ссылки: Контакты, Авторизация         │
└──────────────────────────────────────────┘
Размеры фиксированных зон:

--header-height: 76px (desktop) / 120px (mobile ≤ 768px).

Футер — `position: fixed; bottom: 0`: постоянно виден у нижней границы
окна браузера, поведение одинаково на коротких и длинных страницах.
Футер не уходит вверх вместе с окончанием контента и не появляется
только после прокрутки к концу страницы.

Высота футера определяется содержимым CMS-навигации (ADR-011 §2.23)
и **не фиксируется** значениями 100/120 px. Страница обязана резервировать
пространство под **фактическую** высоту закреплённого футера, чтобы
содержимое не перекрывалось им. Резерв задаётся через CSS-переменную,
значение которой соответствует реальной высоте футера (например,
`--footer-height` обновляется при рендере/изменении CMS-навигации),
либо через эквивалентный механизм с тем же результатом.

Обычный flex-каркас с футером в потоке документа (футер прижат к низу
только за счёт `min-height: 100vh` у `body`) **не является** решением
этого требования: на короткой странице такой футер оказывается сразу
под контентом, а не у нижнего края окна.

Левое меню раздела Players — третья неподвижная часть каркаса: панель
закреплена между фактической нижней границей шапки и фактической верхней
границей футера и не перемещается при прокрутке основного контента.
Реализация, область применения и граничные ограничения — §11.

10. Правила и запреты (обновлено)
Шапка и футер — position: fixed, проверка прокруткой обязательна.

Футер: `position: fixed; bottom: 0` — постоянно виден у нижней границы окна
на коротких и длинных страницах. Высота определяется содержимым CMS
(ADR-011 §2.23), фиксированные 100/120 px не используются.

body { padding-top: var(--header-height); padding-bottom: <фактическая высота футера>; } — без этого контент уезжает под фиксированные зоны. Резерв под футер должен соответствовать его реальной высоте, а не устаревшему фиксированному значению.

Левое меню Players — `position: fixed` между шапкой и футером; при прокрутке
контента оно не перемещается. Сетка раздела продолжает резервировать под него
колонку, поэтому основной контент не смещается. Подробности — §11.

Клик по логотипу → главная страница. Всегда.

Клик по hero-баннеру → главная страница.

Кнопка «Авторизация» — в правом краю шапки, не в центре.

Переключатель темы — только одна иконка, текст не пишем.

Картинки — только из public/img_site через asset().

Ноль логики в Blade — данные приходят готовыми из контроллера.

Никаких табличных раскладок — Flex / Grid.

Галерея (/gallery): каждый раздел — заголовок (section-title) + сетка превью. На странице раздела показывается до 6 фото; если фото больше — остальные доступны внутри раздела. Ряд — ровно 6 фото: CSS Grid repeat(auto-fill, minmax(140px, 1fr)); превью квадратные (aspect-ratio 1/1, object-fit: cover). Внутри раздела — все фото рядами по 6. Клик по фото открывает его на весь экран.

Фиксированное позиционирование шапки — только через селектор body > header (не голый header): внутренние <header> (виджет чата, комментарии) не должны становиться фиксированными и перекрывать навигацию.

Цвета — только из токенов (см. §3). Сомнение → сверка со скриншотом.

Тёмная тема обязательна для всех новых компонентов: проверять через [data-theme="dark"].

Все тексты на русском, как на оригинале.

11. Layout раздела Players

Левое меню — часть общего каркаса раздела (`x-players-layout`, корневой
класс `.players-shell`), а не отдельная вставка на Dashboard. Все
существующие страницы Players, использующие общий layout, получают
одинаковую навигацию автоматически.

Требования:

1. Панель меню закреплена относительно окна (`position: fixed`) и является
   третьей неподвижной частью каркаса после шапки и футера.
2. Верхняя граница панели совпадает с фактической нижней границей
   глобальной шапки, нижняя — с фактической верхней границей футера.
3. Если содержимого меню меньше рабочей высоты между шапкой и футером,
   карточка меню занимает всю эту рабочую высоту.
4. Если содержимого меню больше рабочей высоты, карточка увеличивается по
   содержимому. Высота карточки не фиксируется и не подгоняется под окно;
   пункты меню не обрезаются и не скрываются.
5. При прокрутке основного контента панель меню не перемещается.
6. Меню не имеет собственной вертикальной прокрутки. Единственная
   вертикальная прокрутка — у страницы.
7. Горизонтальное положение и ширина панели рассчитываются по фактической
   колонке сетки. Колонка остаётся в потоке и резервирует место, поэтому
   основной контент не смещается и не попадает под панель.
8. Геометрия пересчитывается при изменении размеров окна, масштаба
   браузера и размеров наблюдаемых элементов.
9. Панель не перекрывает шапку и футер: у них более высокий уровень
   наложения.
10. На экранах ≤1023px сохраняется предусмотренная горизонтальная навигация;
    закрепление относительно окна к ней не применяется.
11. Существующая структура пунктов меню и маршруты остаются без изменений;
    реорганизация навигации — отдельная задача.

Запрещено: `overflow-y: auto/scroll` для меню и основного контента; скрытие
пунктов, подписей или частей карточки ради подгонки под высоту окна.

Граничные ограничения (зафиксированы, не устранены):

- Если суммарная высота шапки, футера и содержимого меню превышает высоту
  окна, меню физически не помещается в рабочую область. Внутренняя
  прокрутка, обрезка и скрытие пунктов для этого случая не вводятся: часть
  карточки может выходить за верхнюю границу футера (в тестовом стенде —
  до 64–82 px при высоте окна 576–594 px), а футер с более высоким уровнем
  наложения перекрывает её нижнюю часть.
- Длинное меню (существенно больше реальных 7 пунктов) по той же причине не
  помещается между шапкой и футером.
- Оба случая сообщаются отдельно и не считаются исправленными.

Критерии приёмки — глобальный футер:

- короткая страница: футер у нижнего края окна;
- длинная страница: футер остаётся у нижнего края при прокрутке;
- содержимое страницы не перекрывается футером;
- проверено на публичных и авторизованных страницах;
- высота футера корректно учитывает динамическое содержимое CMS.

Критерии приёмки — Players:

- при коротком содержимом карточка меню занимает рабочую область между
  шапкой и футером — выполнено (замеры 1440×900 и 1280×720);
- меню не перемещается при прокрутке контента — выполнено;
- нет отдельных вертикальных scroll-контейнеров меню и контента —
  выполнено (`scrollHeight == clientHeight`, `overflow-y: visible`);
- все пункты меню доступны, в том числе нижние пункты длинного меню —
  в пределах доступной высоты окна; при физической нехватке высоты
  действует граничное ограничение (см. выше);
- футер не перекрывает пункты меню — в пределах доступной высоты окна;
- проверены `/players`, `/players/directory`, `/players/characters` —
  визуально владельцем; технические замеры — на тестовом стенде;
- проверены desktop и mobile — desktop: 1440×900, 1280×720, 1024×594,
  масштаб 100 / 125 / 150 %; mobile: 390×844.

Отсутствие внутренних прокруток подтверждается не только
`documentElement.scrollHeight`, но и проверкой computed `overflow-y`,
соотношения `scrollHeight`/`clientHeight` у меню и контента и фактическим
поведением в браузере.
